- The existing SEO tests (`tests/test_site_seo_responsive.py`) pass: 12 of 12.

Open items (copy decisions, not changed here):
1. `/` and `/static/landing.html` have identical content and both canonicalise to `/`. The canonical tag handles this, so no change is needed. Removing `/static/landing.html` would be cleaner.
2. The landing page's hero shows a sample line, "BUY XAU/USD NOW @ 2,320.40 → +0.42% to 2,330.15". It is illustrative, but a crawler or visitor could read it as a live signal. Consider labelling it "example".

## Dependencies

### npm (`package-lock.json`)
- Before: 9 advisories (1 high, 8 moderate). All in build tooling: `wrangler`/`miniflare`/`undici`, `@capacitor/cli`/`xcode`/`uuid`, `glob`/`minimatch`/`rimraf`.
- Production dependencies (`npm audit --omit=dev`): 0 advisories, before and after.
- After `npm audit fix` (no `--force`, `package.json` unchanged): 0 advisories. 18 packages moved, including major bumps in dev-only transitive packages (`xcode` 3→4, `glob` 13→14, `minimatch` 10→11). `wrangler` 4.151.1→4.168.0.
- Verified after the change: `npm run build`, `npm run build:mobile`, `npx cap --version`, `wrangler deploy --dry-run` (bundle builds), `npm run worker:test` (77 pass), `npm run cloudflare:bootstrap:test` (5 pass).

### Python
- `requirements.txt`: no known vulnerabilities (`pip-audit`).
- `requirements-live.txt` (installed by the signal publish, backtest and deploy jobs): `soupsieve` 2.10, pulled in by `yfinance` → `beautifulsoup4`, has 3 advisories (CVE-2026-126190, CVE-2026-126191, CVE-2026-126193). **Not fixed in this change.** The pin `soupsieve>=4.0` was tried and removed. In the sandbox (Python 3.11.2), soupsieve 4.1.3 and 3.0.2 failed on basic CSS selectors, while 2.10 worked. The cause is not confirmed. CI's Python 3.11 runner was not tested. Re-test on Python 3.11.5+ and pin `soupsieve` once the test passes.
